## Эпизод 5. Какие бывают исключения в `std`

**Запрос.** «какие есть исключения в std». Вопрос нужен для требования условия
об осознанной обработке ошибок (раздел 7): в проекте исключения разных типов
выбрасываются в загрузчике, матрице и статистике.

**Получено.** Обзор иерархии, все классы наследуются от `std::exception`:
- `std::logic_error` («ошибки программиста»): `invalid_argument`,
  `domain_error`, `length_error`, `out_of_range`;
- `std::runtime_error` («обнаруживаются только при выполнении»):
  `range_error`, `overflow_error`, `underflow_error`;
- «другие важные»: `bad_alloc`, `bad_cast`, `bad_typeid`, `bad_function_call`,
  `bad_weak_ptr`, `system_error`, `regex_error`.

**Проверка ответа.** Иерархию проверил компилятор (`static_assert` с
`std::is_base_of_v`, сборка `g++ -std=c++20`, все проверки прошли).
В ответе найдены неточности, поэтому его нельзя переносить в README или
защищать как есть:

| Утверждение в ответе | Что на самом деле |
|---|---|
| `system_error` и `regex_error` не входят в две группы | оба наследуются от `std::runtime_error` |
| (не упомянуто) | `std::ios_base::failure` (ошибки потоков, `ifstream`/`ofstream`) наследуется от `system_error`, а `std::filesystem::filesystem_error` (`file_size`, `create_directories` в `main.cpp`) — тоже от `system_error`, то есть оба тоже от `runtime_error` |
| (не упомянуто) | `std::bad_optional_access` и `std::bad_variant_access` наследуются напрямую от `std::exception`, а не от `logic_error`: их выбрасывают `optional::value()` и `std::get` — это важно для кода с `std::optional` и `std::variant` |
| `logic_error` — ошибки, видимые при чтении кода; `runtime_error` — не предсказуемые | это упрощение из документации, а не правило языка: например, `std::stod` на строке `"abc"` выбрасывает `invalid_argument` (логическая группа), хотя причина — данные в файле |

**Связь с проектом.** Что выбрасывается в `src/` (подсчёт по `grep`): 27 раз
`std::runtime_error` (ошибки файлов, формата, нехватка статистики),

## Эпизод 6. Пустой вектор и `size()`

**Запрос.** «`const std::__1::vector<double> &values` если вектор будет пустым и
к нему применить `size()` будет 0?»

**Получено.** Да: у пустого вектора `size() == 0`, `empty() == true`. Опасность в
другом: `size()` имеет беззнаковый тип `std::size_t`, поэтому `values.size() - 1`
при пустом векторе даёт не `-1`, а `18446744073709551615`. Обращения `front()`,
`back()`, `values[0]` и разыменование результата `std::minmax_element` для пустого
диапазона — неопределённое поведение.

**Связь с проектом.** `get_quantile` вычисляет `probability * (values.size() - 1)`,
поэтому в начале функции стоит проверка `values.empty()` с исключением
`std::invalid_argument`; `get_numeric_statistics` возвращает до расчёта min/max,
если все значения столбца пропущены; `get_numeric_histogram` возвращает пустой
результат при пустом входе. Тесты `test_all_missing` и проверка
`get_quantile(std::vector<double>{}, 0.5)` в `tests/test_statistics.cpp` покрывают
этот случай.

## Эпизод 7. `std::from_chars`, `std::stringstream`, `std::span`

**Запрос.** «`std::from_chars`, `std::stringstream`, `std::span` как использовать».

**Получено.** Разбор трёх средств для разбора чисел и передачи массивов.

| Средство | Как использовать | Особенности |
|---|---|---|

## Эпизод 8. Ошибки линковки `Undefined symbols for architecture arm64` (3 запроса)

Три запроса об одном классе ошибки.

**Запрос 1.** «разбор ошибки Undefined symbols for architecture arm64:
`"get_statistics(NumericColumn const&)", referenced from: _main in main.cpp.o` /
`ld: symbol(s) not found for architecture arm64` / `clang++: error: linker command
failed with exit code 1 (use -v to see invocation)` / `make[2]: *** [lab1] Error 1`
…; `zsh: no such file or directory: ./build/lab1`».

**Запрос 2.** «разбор ошибки Undefined symbols for architecture arm64:
`"get_histogram(std::__1::vector<double, std::__1::allocator<double>> const&,
unsigned long)", referenced from: get_statistics(NumericColumn const&, unsigned
long) in statistics.cpp.o` / `ld: symbol(s) not found …`».

**Запрос 3.** «разбор ошибки Undefined symbols for architecture arm64:
`"preprocess_dataset(Dataset const&, DatasetInfo const&, NumericRefill, Scaling,
CategoricalEncoding)", referenced from: _main in main.cpp.o` / `ld: symbol(s) not
found …` / `make[2]: *** [lab1] Error 1`».

**Получено.** Это ошибка **линковщика**, а не компилятора: каждый `.cpp` успешно
скомпилирован, но в объектных файлах нет определения функции с точно такой
сигнатурой, которую кто-то вызывает. `ld` ищет символ по полному имени, включая
типы всех параметров, поэтому «почти такая же» функция не подходит. Типичные
причины:

1. функция объявлена в заголовке, но нигде не определена;
2. сигнатуры объявления и определения расходятся (число параметров, `const`,
   `&`, тип: `std::vector<double> const&` и `std::span<const double>` — разные
   символы);

## Эпизод 9. Выравнивание гистограммы в консоли

**Запрос.** «как сделать так, чтобы символы `#` начинались с одинаковой позиции
в каждой строке» (пример: интервалы `[4.5, 133.8)`, `[133.8, 263.1)`, … и
столбцы `###…` с числами) «для с++20».

**Получено.** Строки разной длины сдвигают столбец `#`. Нужно дополнить подпись
интервала до фиксированной ширины:
- `std::cout << std::left << std::setw(W) << interval << bar << ' ' << count`
  (`setw` действует только на следующий вывод, `std::left` сохраняется);
- в C++20 удобнее `std::format("{:<16}{:<30}{}", interval, bar, count)`;
- ширину `W` лучше вычислить как максимальную длину подписи среди всех
  интервалов, а не подбирать числом вручную.

**Связь с проектом.** В `print_numeric_statistics` (`main.cpp`) подпись интервала
дополняется `std::setw(18)`, ширина полосы задаётся переменной
`max_bar_length`; числа в подписях формируются через `std::format("{:.1f}", …)`.

**Принято / изменено / отклонено:** [заполнить: оставили фиксированные 18 для подписи
или вычисляете ширину по самой длинной подписи].

**Проверка.** Отдельная программа: без `setw` столбец `#####` смещается, с
`setw`/`std::format` совпадает во всех трёх строках.

## Эпизод 10. Один знак после запятой

**Запрос.** «`double x = 5.0 / 3.0;` как мне сделать так, чтобы у `x` был один
знак после запятой» (ответ: `std::fixed` + `std::setprecision`).

**Получено.** `std::cout << std::fixed << std::setprecision(1) << x;` печатает
`1.7`. Без `std::fixed` число в `setprecision(1)` означает количество **значащих
цифр** и даёт `2`. Оба манипулятора «залипают» для последующего вывода в этот
поток. Альтернатива в C++20: `std::format("{:.1f}", x)` ничего не меняет в
потоке.

**Связь с проектом.** `print_numeric_statistics` использует
`std::fixed << std::setprecision(3)`, подписи интервалов гистограммы —
`std::format("{:.1f}", …)`.

**Принято / изменено / отклонено:** [заполнить].

**Проверка.** Вывод `5.0/3.0`: по умолчанию `1.66667`, `setprecision(1)` без
`fixed` → `2`, `fixed` + `setprecision(1)` → `1.7`, `std::format` → `1.7`.
