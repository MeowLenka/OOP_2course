## Эпизод 6. Пустой вектор и `size()`

**Запрос.**

```text
const std::__1::vector<double> &values если вектор будет пустым и к нему применить size() будет 0?
```

**Получено.** Да, у пустого вектора `size() == 0` и `empty() == true`.

Опасность в другом: `size()` возвращает беззнаковый `std::size_t`, поэтому
`values.size() - 1` при пустом векторе равно не `-1`, а `18446744073709551615`.
Кроме того, для пустого вектора неопределённое поведение дают `front()`, `back()`,
`values[0]` и разыменование результата `std::minmax_element`.

**Где это важно в проекте.**

| Место | Как защищено |
|---|---|
| `get_quantile` (позиция `p · (size − 1)`) | в начале проверка `values.empty()` → `std::invalid_argument` |
| `get_numeric_statistics` (min, max, mean) | если все значения столбца пропущены, функция возвращает результат до расчётов |
| `get_numeric_histogram` | при пустом входе возвращает пустую гистограмму |

Тесты: `test_all_missing` и проверка `get_quantile(std::vector<double>{}, 0.5)` в
`tests/test_statistics.cpp`.

**Принято / изменено / отклонено:** [заполнить].

**Проверка.** Отдельная программа с пустым `const std::vector<double>`:
`size=0 empty=1 size-1=18446744073709551615`.

## Эпизод 7. `std::from_chars`, `std::stringstream`, `std::span`

**Запрос.**

```text
std::from_chars, std::stringstream, std::span как использовать
```

**Получено.**

| Средство | Как использовать | Особенности |
|---|---|---|
| `std::from_chars(first, last, value)` (`<charconv>`) | возвращает `{ptr, ec}`; успех — `ec == std::errc{}`; токен разобран целиком, если `ptr == last` | не бросает исключений; **не пропускает пробелы** и **не принимает ведущий `+`**; `"12x"` даёт успех, но `ptr` указывает на `x`; при `result_out_of_range` значение не меняется |
| `std::istringstream` (`<sstream>`) | `in >> value`; ошибка — `in.fail()` | читает один токен, остаток строки надо проверять отдельно; зависит от локали; медленнее |
| `std::span<const double>` (`<span>`) | неявно создаётся из `std::vector<double>`; `size()`, `empty()`, `[]`, `subspan(offset, count)` | не владеет памятью и не копирует; существует не дольше исходного массива |

**Результаты запуска `from_chars`:**

| Строка | Результат |
|---|---|
| `"3.5"` | успех, разобрана целиком |
| `"abc"` | `invalid_argument` |
| `"12x"` | успех, но разобрана не целиком |
| `" 7"` | `invalid_argument` (пробел не пропускается) |
| `"+4"` | `invalid_argument` (плюс не принимается) |
| `"1e999"` | `result_out_of_range`, значение не изменено |

**Связь с проектом.** `std::span` используется в `get_quantile` и
`get_numeric_histogram`. Разбор чисел в `is_number` и `parse_number` сделан через
`std::stod` с проверкой `pos == value.size()`; `from_chars` и `stringstream` в
проекте не применяются.

Оговорка: поддержка `from_chars` для `double` в стандартной библиотеке Apple
(libc++) появилась позже, чем в libstdc++, и на старых версиях Xcode может не
собираться. Это не проверялось (примеры запускались на libstdc++).

**Принято / изменено / отклонено:** [заполнить: какой способ разбора выбрали и
почему].

**Проверка.** Отдельная программа: `from_chars` на строках из таблицы;
`istringstream` на `"3.5 abc"` (число и слово читаются) и `"abc"` (`fail() == true`);
`span` и `subspan(1, 3)` на `{1, 2, 3, 4, 5}` (суммы 15 и 9).

## Эпизод 8. Ошибка линковки: `get_statistics`

**Запрос.**

```text
разбор ошибки Undefined symbols for architecture arm64:
  "get_statistics(NumericColumn const&)", referenced from:
      _main in main.cpp.o
ld: symbol(s) not found for architecture arm64
clang++: error: linker command failed with exit code 1 (use -v to see invocation)
make[2]: *** [lab1] Error 1
make[1]: *** [CMakeFiles/lab1.dir/all] Error 2
make: *** [all] Error 2
elenat@MacBook-Pro-elenatashlykova OOP % ./build/lab1
zsh: no such file or directory: ./build/lab1
```

**Получено.**

Это ошибка **линковщика**, не компилятора: все `.cpp` скомпилировались, но в
объектных файлах нет определения функции с точно такой сигнатурой, которую вызывает
`main`. Линковщик ищет символ по полному имени вместе с типами всех параметров, и
«почти такая же» функция не подходит.

Что видно из текста:
- `referenced from: _main in main.cpp.o` — функция вызывается из `main`;
- имя символа `get_statistics(NumericColumn const&)` — вызывается версия с
  **одним** параметром;
- следующие запросы показывают, что в `statistics.cpp` определена версия с двумя
  параметрами (`get_statistics(NumericColumn const&, unsigned long)`). Значит,
  вероятная причина — расхождение сигнатур между объявлением в заголовке и
  определением: объявлена одна форма, определена другая.

Строка `zsh: no such file or directory: ./build/lab1` — не отдельная ошибка:
исполняемый файл не создаётся, пока линковка не прошла.

Что проверить, по порядку:
1. сигнатура в `.hpp` и в `.cpp` совпадает (число параметров, `const`, `&`, типы);
2. у функции есть определение, а не только объявление;
3. `.cpp` с определением перечислен в `CMakeLists.txt`;
4. определение не оказалось в `namespace {}` или в другом пространстве имён.

**В итоговом проекте:** функции переименованы в `get_numeric_statistics` и
`get_categorical_statistics`; `bin_count` передаётся вторым параметром явно.

**Принято / изменено / отклонено:** [заполнить: что оказалось причиной и как
исправили].

**Проверка.** Ошибка воспроизведена на g++ (там она называется
`undefined reference`) расхождением сигнатур; после согласования сигнатур
программа собирается.

## Эпизод 9. Ошибка линковки: `get_histogram`

**Запрос.**

```text
разбор ошибки Undefined symbols for architecture arm64:
  "get_histogram(std::__1::vector<double, std::__1::allocator<double>> const&, unsigned long)", referenced from:
      get_statistics(NumericColumn const&, unsigned long) in statistics.cpp.o
ld: symbol(s) not found for architecture arm64
clang++: error: linker command failed with exit code 1 (use -v to see invocation)
```

**Получено.**

Отличие от эпизода 8: функция вызывается не из `main`, а из другой функции
библиотеки (`referenced from: get_statistics(...) in statistics.cpp.o`). Значит,
`statistics.cpp` компилируется и объявление `get_histogram` в заголовке есть, а
определения с точно такой сигнатурой в собранных файлах нет.

В имени символа `std::__1` — внутреннее пространство имён libc++ (Apple); в
своём коде это `std::vector<double> const&` и `std::size_t`.

Причины, которые нужно проверить:
1. определение лежит в другом `.cpp` (например, `histogram.cpp`), который не
   добавлен в `add_library` / `add_executable`;
2. тип первого параметра в определении другой: `std::vector<double> const&` и
   `std::span<const double>` — **разные** символы;
3. разный тип второго параметра (`unsigned long` = `std::size_t`);
4. определено только объявление.

Как посмотреть, какие символы реально определены в библиотеке:
`nm build/liblab_core.a | c++filt | grep histogram`.

**В итоговом проекте:** `get_numeric_histogram(std::span<const double>, std::size_t)`
и `get_categorical_histogram(const std::vector<std::string>&)` объявлены в
`statistics.hpp`, определены в `histogram.cpp`; `histogram.cpp` есть в списке
`add_library(lab_core …)`.

**Принято / изменено / отклонено:** [заполнить: какая из причин оказалась вашей].

**Проверка.** Воспроизведено на g++: заголовок с `std::vector<double> const&`,
определение с `std::span<const double>` → `undefined reference`; определение в
файле, не переданном компилятору → та же ошибка; согласованные сигнатуры и оба
файла в сборке → программа собирается и запускается.

## Эпизод 10. Выравнивание `#` в гистограмме

**Запрос.**

```text
как сделать так , чтобы символы # начинались с одинаковой позиции в каждой строке
  [4.5, 133.8) ##############################   591
  [133.8, 263.1) #                                16
  [263.1, 392.3) #                                4
  [392.3, 521.6) #                                3
  [521.6, 650.9) #                                1
для с++20
```

**Получено.**

Подписи интервалов разной длины сдвигают столбец `#`. Подпись нужно дополнить
пробелами до одной ширины:

```cpp
std::cout << std::left << std::setw(W) << interval << bar << ' ' << count << '\n';
```

- `std::setw` действует только на следующий вывод; `std::left` «залипает»;
- в C++20 удобнее `std::format("{:<16}{:<30}{}", interval, bar, count)`;
- ширину `W` лучше вычислять как максимальную длину подписи среди всех
  интервалов, а не подбирать числом вручную.

**Связь с проектом.** В `print_numeric_statistics` (`main.cpp`) подпись интервала
дополняется до 18 символов (`std::setw(18)`), ширина полосы задаётся переменной
`max_bar_length`; числа в подписях формируются через `std::format("{:.1f}", …)`.

**Принято / изменено / отклонено:** [заполнить: оставили фиксированные 18 или
вычисляете ширину по самой длинной подписи].

**Проверка.** Отдельная программа: без `setw` столбец `#####` смещается, с
`setw` и с `std::format` совпадает во всех строках.

## Эпизод 11. Один знак после запятой

**Запрос.**

```text
double x = 5.0 /3.0;
как мне сделать так, чтобы у x был один знак после запятой (ответ std::fixed + std::setprecision )
```

**Получено.**

```cpp
std::cout << std::fixed << std::setprecision(1) << x;   // 1.7
```

| Способ | Вывод `5.0 / 3.0` |
|---|---|
| по умолчанию | `1.66667` |
| `std::setprecision(1)` без `std::fixed` | `2` (одна **значащая цифра**) |
| `std::fixed` + `std::setprecision(1)` | `1.7` |
| `std::format("{:.1f}", x)` (C++20) | `1.7` |

`std::fixed` и `std::setprecision` «залипают» для последующего вывода в этот
поток; `std::format` поток не меняет.

**Связь с проектом.** `print_numeric_statistics` использует
`std::fixed << std::setprecision(3)`, подписи интервалов гистограммы и процент
пропусков в сводке — `std::format("{:.1f}", …)`.

**Принято / изменено / отклонено:** [заполнить].

**Проверка.** Отдельная программа: все четыре варианта дали значения из таблицы.
