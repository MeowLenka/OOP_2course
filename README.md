# Лабораторная работа 1. Загрузка, анализ и предобработка табличных данных

Консольная программа на C++20: загружает CSV с пропусками, определяет типы
признаков, считает и выводит статистику, по запросу выполняет предобработку и
сохраняет итоговую матрицу в бинарном виде.

## 2. Конфигурация загрузчика

Все обозначения, специфичные для датасета, заданы в одном месте — структуре
`CsvConfig` (`include/csv_loader.hpp`):

```cpp
struct CsvConfig
{
    char separator = ',';
    std::string skip_value = "NA";
    bool has_header = true;
};
```

Дополнительно загрузчик:

- убирает `\r` в конце строки и пропускает пустые строки;
- считает пустое поле пропуском так же, как `NA`.

Количество признаков, их имена и типы определяются из файла, а не заданы в
коде: порядок столбцов, число столбцов и число строк можно менять без правки
кода.

**Проверка согласованности.** Если число полей в какой-то строке не совпадает с
заголовком, загрузка прерывается с сообщением вида
`Неверное количество полей в строке 5` (номер — номер строки в файле).
Несуществующий и пустой файл тоже дают понятную ошибку.

**Пропуск** хранится как `std::nullopt` в `std::optional<double>` /
`std::optional<std::string>`, а не как особое число или пустая строка.

## 3. Правило определения типа признака

Для каждого столбца берутся все значения, кроме пропусков:

1. если **все** значения целиком разбираются как число (`std::stod`, весь токен
   должен быть использован) — признак **числовой**;
2. если хотя бы одно значение не разбирается как число — **категориальный**;
3. если в столбце нет ни одного непропущенного значения — **категориальный**.

Порога по числу уникальных значений нет.

**Результат на этом датасете.** `Category` и `Sex` — категориальные,
`Age` и все лабораторные показатели — числовые, технический столбец —
числовой. Все признаки определились верно: в файле нет числовых кодов,
которые на самом деле обозначают категории.

**Ограничение правила.** Столбец вроде «0/1/2», где числа обозначают
категории, был бы определён как числовой. Для HCV такого столбца нет; для
другого датасета потребовался бы порог.

## 4. Статистика

Считается по **исходным данным** — до заполнения пропусков и любых
преобразований; пропуски в расчётах не участвуют. Результаты лежат отдельно от
данных (`DatasetInfo`) и датасет не изменяют.

Числовой признак: число пропусков, `min`, `max`, среднее, дисперсия, квантили
`q05`, `q25`, `q50`, `q75`, `q95`, гистограмма.

Категориальный признак: число пропусков, список категорий, гистограмма по
категориям.

Решения:

- **Дисперсия** — генеральная, с делением на `n` (не `n − 1`).
- **Квантили** — линейная интерполяция между соседними элементами
  отсортированного массива: позиция `p · (n − 1)` (как `numpy.percentile` с
  методом `linear`).
- **Гистограмма** — равные интервалы между `min` и `max`; число интервалов
  по умолчанию 7, задаётся `--bins`. Максимум попадает в последний интервал.
  Если `min == max`, все значения попадают в первый интервал.
- Категории отсортированы по алфавиту.

Статистические функции принимают данные как `std::span<const double>`.

## 5. Предобработка

Выполняется по запросу пользователя (или сразу, если задан `--output`).

### 5.1. Заполнение пропусков

| Признак | Стратегия (`--refill`) |
| числовой | `median` (по умолчанию), `mean` или `zero` |
| категориальный | дополнительная категория `__MISSING__` |

Используется **уже вычисленная** статистика: медиана и среднее не
пересчитываются по данным, в которые подставлены значения. Предобработка
работает с копией датасета, поэтому исходные данные остаются с пропусками.

Служебная категория `__MISSING__` добавляется только в список категорий для
кодирования; в статистике (`DatasetInfo`) исходный набор категорий не
меняется. В HCV пропусков в категориальных признаках нет, поэтому
`__MISSING__` в итоговой матрице не появляется.

### 5.2. Масштабирование числовых признаков (`--scaling`)

| Значение | Формула | Примечание |
|---|---|---|
| `standard` (по умолчанию) | `(x − μ) / σ` | σ = √дисперсии из статистики |
| `minmax` | `(x − min) / (max − min)` | |
| `robust` | `(x − q50) / (q75 − q25)` | устойчиво к выбросам |

Нужные величины берутся из уже вычисленной статистики.

**Вырожденный случай** (знаменатель равен нулю: константный признак или
`q75 == q25`): результат `0.0`.

**Почему стандартизация по умолчанию.** Лабораторные показатели имеют разные
единицы и масштабы (`ALP` в сотнях, `CHE` в единицах), а модели следующих
работ чувствительны к масштабу. Для признаков с сильными выбросами (`GGT`,
`ALT`) лучше подходит `robust`.

### 5.3. Кодирование категориальных признаков (`--encoding`)

| Значение | Результат |
|---|---|
| `onehot` (по умолчанию) | по столбцу на категорию, значения 0/1, имена `Sex_f`, `Sex_m` |
| `ordinal` | один столбец с целочисленным кодом, имя — исходное (`Sex`) |

**Порядок категорий детерминирован:** категории отсортированы по алфавиту,
`__MISSING__` (если нужен) — всегда последняя. Код `ordinal` равен позиции
категории в этом списке. Одинаковый вход даёт одинаковые номера столбцов и
коды.

**Почему one-hot по умолчанию.** Категории `Sex` и `Category` не упорядочены;
one-hot не вводит между ними порядка.

**Ordinal и ложный порядок.** Код `0, 1, 2…` задаёт между категориями порядок
и «расстояния», которых в данных нет. Это искажает линейные модели, k
ближайших соседей, SVM, нейронные сети — модели, использующие значения
признака как числа. Для деревьев решений и ансамблей на их основе ordinal
почти не мешает: они сравнивают значения порогами и могут выделить любую
категорию серией разбиений.

### 5.4. Результат

Плотная числовая матрица `Matrix` (по умолчанию `RowMajor`) и вектор имён
`feature_names`: `feature_names[j]` — имя столбца `j` матрицы. Технический
столбец в матрицу не включается.

Для HCV с параметрами по умолчанию: 615 строк × 18 столбцов
(`Category` → 5, `Sex` → 2, `Age` → 1, десять лабораторных → 10).

## 6. Бинарный формат

Файл записывается и читается методами `Matrix::save` / `Matrix::load`.

| Смещение | Размер | Содержимое |
|---|---|---|
| 0 | 8 байт | число строк, `uint64_t` |
| 8 | 8 байт | число столбцов, `uint64_t` |
| 16 | 1 байт | порядок хранения: `0` — RowMajor, `1` — ColumnMajor |
| 17 | `8 · rows · cols` | элементы `double` (IEEE 754) без текстового преобразования |

Размер файла: `17 + 8 · rows · cols` байт. Для матрицы 615 × 18 это
`17 + 88 560 = 88 577` байт.

**Загрузка:** сначала читается заголовок, проверяются `layout` и отсутствие
переполнения `rows · cols`, затем выделяется память под матрицу и только после
этого читается массив. Обрезанный файл, слишком короткий файл и несуществующий
файл дают исключение, а не аварийное завершение.

**Сравнение с CSV.** После сохранения программа печатает размеры файлов:

```
CSV:    44953 байт
Binary: 88577 байт
```

Здесь бинарный файл **больше** исходного CSV. Исходный CSV хранит короткие
значения вроде `38.5` и `7` (по 1–5 символов), а матрица содержит 18 столбцов
вместо 13 (после one-hot) и по 8 байт на каждое число. Выигрыш бинарного
формата — в скорости чтения и отсутствии потерь точности, а не в размере.

**Почему формат подходит только для учебной задачи:**

- не учитывается **порядок байтов**: файл копирует представление `double` в
  памяти, поэтому на машине с другим порядком байтов прочитается неверно;
- предполагается, что `double` — 8 байт в формате IEEE 754 (ширина размеров
  зафиксирована через `uint64_t`, но для `double` это не проверяется);
- нет **версии формата** и сигнатуры (magic number): нельзя отличить наш файл
  от любого другого и нельзя изменить формат без поломки старых файлов;
- нет **контроля целостности** (контрольной суммы): повреждённые значения
  читаются без ошибки;
- размеры из заголовка не сверяются с реальным размером файла до выделения
  памяти: испорченный заголовок может привести к попытке выделить огромный
  массив.

```text

│   ├── csv_loader.cpp  statistics.cpp  histogram.cpp

```

Логика загрузки, анализа и преобразования лежит в библиотеке `lab_core`;
ввод-вывод для пользователя — в `src/main.cpp`.

Поток данных:

```
CSV -> Dataset -> get_dataset_info() -> DatasetInfo -> печать статистики
          |                                  |
          +-- copy -> impute_missing_values(info)
                          -> transform_dataset(info) -> Matrix + feature_names -> .bin
```

Стратегии заданы через `enum class` (`NumericRefill`, `Scaling`,
`CategoricalEncoding`, `Layout`); разбор строки из командной строки в
перечисление изолирован в трёх функциях `parse_*` в `main.cpp`.

## 8. Сборка и запуск

Требования: компилятор с поддержкой C++20 (`<format>`, `<span>`), CMake ≥ 3.20.

### Сборка (Debug, с AddressSanitizer и UndefinedBehaviorSanitizer)

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j
```

Debug — тип сборки по умолчанию. Флаги `-Wall -Wextra` включены всегда.

### Сборка Release

```bash
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release
cmake --build build-release -j
```

### Запуск

```bash
./build/lab1 --csv data/dataset.csv                       # интерактивно
./build/lab1 --csv data/dataset.csv -o data/result.bin     # сразу сохранить матрицу
./build/lab1 --help
```

Если `--csv` не указан, путь запрашивается у пользователя.

В цикле просмотра статистики вводится номер признака от `1` до числа
признаков; `0` завершает цикл. Некорректный ввод (не число, номер вне
диапазона) сообщается и цикл продолжается. Перед выходом программа спрашивает,
нужно ли выполнить предобработку и сохранить результат.

### Параметры командной строки

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--csv <путь>` | запрос у пользователя | входной CSV |
| `-o, --output <путь>` | — | выходной `.bin`; если задан, предобработка выполняется без вопросов |
| `--bins <N>` | `7` | число интервалов гистограммы (`N > 0`) |
| `--refill` | `median` | `median`, `mean`, `zero` |
| `--scaling` | `standard` | `standard`, `minmax`, `robust` |
| `--encoding` | `onehot` | `onehot`, `ordinal` |
| `-h, --help` | — | справка |

Некорректное значение параметра — сообщение в `stderr` и код возврата `1`.

### Просмотр сохранённого .bin

```bash
./build/bin_viewer out/result.bin        # размеры и первые 5 строк
./build/bin_viewer out/result.bin 10     # первые 10 строк
```

## 9. Тесты

Тесты — отдельные программы без фреймворка (`tests/test_utils.hpp`):
при несовпадении печатают файл и строку и возвращают ненулевой код. Проверки
работают и в Release (в отличие от `assert`). Все тесты зарегистрированы в
CTest и в Debug выполняются под ASan/UBSan.

```bash
cmake --build build -j
ctest --test-dir build --output-on-failure    # запуск всех тестов
ctest --test-dir build -V                     # с выводом (в т.ч. первые строки матрицы)
ctest --test-dir build -R test_matrix         # один тест по имени
./build/test_matrix                           # запуск напрямую
```

| Тест | Что проверяет |
|---|---|
| `test_csv_loader` | разбор строки с пропуском `NA` → `nullopt`; кавычки (запятая и `""` внутри поля); определение типа признака; несогласованный CSV (ошибка с номером строки); несуществующий и пустой файл |
| `test_statistics` | квантили на известных массивах (нечётная/чётная длина, 1 элемент, ошибки); min, max, mean, var, `q05…q95` с пропуском; признак из одних пропусков; категории и частоты |
| `test_preprocessing` | one-hot и ordinal (значения, порядок категорий, имена столбцов); `__MISSING__`; три стратегии заполнения; три масштабирования по исходной статистике; исходные данные и статистика не изменяются; технический столбец пропущен |
| `test_matrix` | цикл «запись → чтение → сравнение» (точное сравнение) для RowMajor, ColumnMajor и пустой матрицы; размер файла `17 + 8·rows·cols`; обрезанный, слишком короткий и несуществующий файл; выход за границы; печать первых строк загруженной матрицы |
